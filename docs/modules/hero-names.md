# 英雄名称：--names 与 --labels

文件：

- `core/hero_names.py`：VLM 命名 + 本地缓存（`--names`）
- `core/hero_match.py`：人工标注最近邻（`--labels`）

棋盘上的 3D 棋子 OCR 读不出名字，所以单独做成可选步骤，不影响默认主流程。

## 共同前置

两个模式都基于 `board_units.extract()` 的 `box`（血条框），用 `crop_unit()` 裁棋子本体：

- 血条在棋子头顶，主体在血条下方。
- 裁剪范围：血条宽度 `w`，左右各 `0.10w`，上 `0.10w`，下 `1.45w`。
- 比早期 0.35/2.2 的宽松版本更紧，避免把隔壁棋子带进来。

描述子 `desc()`：

- 灰度 → 16×16 → 高斯模糊 1.4 → 零均值单位方差。
- 输出 256 维向量。
- 实测：同单位平移 ±3px 余弦 ≥0.98，JPEG q60 ≥0.998，不同单位 ≤0.90。
- 阈值 `SIM_MIN = 0.94`。

## `--names`：VLM + 缓存

流程：

1. 每个单位裁图、算描述子。
2. 查 `data/hero_names_cache.json`，按「描述子 + 星级」找余弦 ≥0.94 的缓存。
3. 命中直接用（约 25ms，0 请求）。
4. 未命中且本轮内不重复的棋子，拼成一张 4 列编号九宫格，**一次 VLM 请求**认完。
   - 每格 `TILE=224`；112px 时模型对同一张图会给不同答案。
   - 输出 JSON：`{"1":"薇恩",...}`，认不出写 `null`。
5. 名字必须能匹配 S18 名单才写缓存：
   - 名单来自 `data/s18db/heroes.json` 的 65 个英雄名；
   - 同时收 `title` 作为称号别名（如「翠神」→「艾翁」）；
   - 先精确匹配，再别名，再 `difflib` 近似（cutoff 0.6）。
6. 认不出的记「未知」，同一描述子试满 3 次后不再请求。

输出字段（每个 unit）：

```json
{"name": "瑟庄妮", "name_src": "cache", "name_score": 0.987}
```

`name_src`：`cache` 或 `vlm`。`scan.py` 还会输出 `_名字统计`：
`{"hits","skipped","unique","vlm_calls","vlm_ms","cache_size"}`。

缓存写入是「临时文件 + `os.replace`」，避免中断损坏。

### 为什么缓存会「变粘」

VLM 第一次答错的名字会被缓存复用。当前只缓存通过名单校验的结果，能挡掉一部分错误；但仍不能保证准确率。

### 现状

- **没有可信准确率数字**。棋子在画面里只有 50~70px，放大到 224 不增加信息。
- 用羁绊面板反推暂不可用：`s18db` 部分英雄羁绊缺失，且面板 count/tiers 在部分布局下会错位。
- 结论：`--names` 是实验性开关，默认关闭。

## 离线匹配：`--labels`

流程：

1. 读 `data/hero_labels/labels.json`（labeler 产出，按裁剪图 sha1 去重）。
2. 每条标注的 `crops/<sha1>.png` 算同样的 256 维描述子，建索引。
3. 新棋子做最近邻，余弦 ≥0.94 才给名字；否则留空，只给 `name_top` 前 3 候选。
4. 输出 `name_src="label"`。

实测（12 条标注）：

| 图像 | 结果 |
|---|---|
| 标注来源那张图（16:9） | 12/12 命中，全部 1.000 |
| 另一张不同地图/宽屏 | 0/5，最高 0.39~0.80，全部判不出 |

结论：

- 同源匹配可靠：换回合、同分辨率能稳定认出。
- 跨地图/跨宽高比不行：描述子混进了地面纹理，换背景就失效。
- 标注越多、覆盖地图/皮肤越多，命中率才会上来。

## 已知限制

- `--names` 会联网；`--labels` 完全离线（约 13ms）。
- 两者都依赖 `board_units` 的血条框；血条漏检就没有名字。
- `--labels` 需要 `data/hero_labels/` 有足够标注；当前只有 12 条。
- 缓存/标注都可能带错，低分时宁可不给名字（当前实现会留空并给候选）。
- `core/hero_names.py` 的 `__main__` 里有一个 `D:\Download\...` 样例路径，仅用于开发调试。
