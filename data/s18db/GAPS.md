## P0 — 仍然阻塞

### 1. 阵容统计的口径不足
- **已有**：27 套，`tier`、`playRate`、`top4Rate`、`winRate`、`avgPlace`、`score`、`difficulty`、`tags`；
  `meta.sampleCount` = 814,416（统计窗口内对局总数），可推算每套阵容的样本量 ≈ `playRate × sampleCount`。
- **缺**：
  - **段位分桶**（大师/宗师/王者）——现在是一个混合池；
  - 统计窗口的具体起止时间（只有 `updateTime`）；
  - `sampleCount` 的精确口径（是「对局数」还是「上榜阵容数」需要向站点确认）。
- **影响**：无法做置信度加权，也无法「按你的段位」给建议。

### 2. 仙灵（wisps）没有强度数据
- **已解决**：强化符文（= 强化果实）现在有两套独立数据 —— 站点评级 `augments_tier.json`（246 条 S/A/B/C/D）+ dataj.cc 真实统计（235 条，含样本量、出场率、平均名次、前四率、吃鸡率、3-2/4-2 分阶段）。
- **仍缺**：20 条强化符文在 dataj 统计页里没有（烧起来、星界赐福 I、集中火力、兽性本能×2、致命丽花、三相庇护、挑个好伙计、好事成双、存心失利、意外之礼/＋、新纪元、四费增援、光明无赖、弈子套娃×2、意料之中的意外、生日礼物、窃贼帮派 II）。
- **仍缺**：181 条**仙灵**（wisps）只有类别/费用/前置条件/效果，没有选取率或强弱排序。
- **影响**：AI 能说「3-2 该拿哪个强化符文」，但说不出「这两个仙灵选哪个」。
- **可能来源**：dataj.cc 只有 `/hex`（强化符文）页，没有仙灵统计；需要外部数据或从对局数据统计。

### 3. 技能与羁绊的结构化语义
- **技能**：`hero_skills_tags.json` 给 65 个技能标了 `damageType / targeting / cc / utility / summon / scaling / tags`；
  `heroes.json` 的 `skill.starScaling` 已把 156/164 行数值拆成 `{1星,2星,3星(,4星)}`。
  但标签是规则归类、**未逐条人工确认**；被动与主动混排的技能只按主要效果归类。
- **羁绊**：`traits.json` 的 `breakpoints[].effects` 覆盖 91/91 档（61 档有数值），
  但 `mechanic` 类（悬赏令/月相/种子/兽灵赐福/配对）只是标签 + 备注，不是可执行规则；
  同一档位出现两个同属性值（如主宰 4%/20% DR）时没区分「基础值 / 条件触发值」。
- **仍缺**：技能的星级成长曲线没有结构化（靠 `heroes.json` 的 `breakdown` 原始数组），被动与主动混排的技能只按主要效果归类。

### 4. 装备：数值已解决，配方只覆盖 55 件
- **已解决**：`items.json` 的 `stats` 从站点 `effectAttr` 解析出 131/151 件的结构化属性（AD/AP/HP/护甲/魔抗/攻速/暴击/法力回复/伤害增幅/全能吸血/减伤）。
- **仍缺**：
  - 剩下 20 件（冠冕、各类纹章、药水、宝箱）站点没有数值；
  - 合成路径只有 55 条（39 成装 + 16 纹章），且来源是项目原有的 `data/EquipmentData.json`，不是站点；
  - 光明装/奥恩神器没有合成路径（本身也不需要），但「散件 → 成装」的完整矩阵共有 10×10 组合，目前只覆盖了实际存在的 39 件成装。

### 5. 补丁元数据
- 只有版本字符串（`18.5b` 榜单 / `18.5c` 资料库），没有改动日志，解释不了强度变化。

## P1 — 影响推荐质量

| 项 | 现状 | 缺什么 |
|---|---|---|
| 阵容克制/对位 | 无 | comp A vs comp B 的胜率或名次差 |
| 同行竞争 | 有卡池 30/25/18/10/9、商店概率 | 某单位在 N 家同行下的期望搜索成本 |
| 站位语义 | 有 slot/row/col | 前/后排标签、对位微调规则（躲刺客/AOE） |
| 经济节奏 | 有经验/利息/连胜/阶段伤害，回合金币只到 2-2 | 每阶段标准血线、标准经济曲线、梭哈阈值 |
| 英雄强化 | 无 | 弈子 ↔ 英雄强化映射、出现率 |
| 特殊机制 | 仙灵互斥 181 条 | 触发→收益的结构化；棋盘 `hexs` 编码未解码成名称 |
| 阵容覆盖面 | 27 套 | 榜单只收「主流成型阵容」，缺冷门/环境应对 |

## 数据本身的坑（已确认）

- 榜单接口对 `16292`、`16264` 返回空数据（站点已下架），所以是 27 套而不是 29 套。
- 部分阵容棋盘含 `999001`~`999004` 占位单位，站点前端也没有中文名 → 存在 `board.extras`，未计入 `units`。
- `stars` 为空表示站点未标注（渲染时也不显示星标），通常按 2 星理解。
- `board.hexs` 是强化符文/特殊格的 2 字符编码，尚未解码成具体名称。

## 输入侧：AI 还需要知道「你这局是什么状态」

`scan.py` 目前能读：**阶段 / 等级 / 经验 / 金币 / 商店 5 张卡 / 棋子数量**。

| 缺的输入 | 难度 | 备注 |
|---|---|---|
| 当前血量 | 低 | OCR 一行数字 |
| 装备栏（散件/成装） | 中 | 图标库已在 `data/equipment_s18/`（136 张） |
| 已拿强化符文/果实 | 中 | 图标 + 名称识别 |
| 场上棋子身份 | **高** | 3D 棋子 OCR 不可用，需逐格模板匹配 + 羁绊约束求解 |
| 备战席 | 中 | 同棋子识别 |
| 对手阵容 | 高 | 通常不可得 |

## 建议的补齐顺序

1. **技能语义标签化**（P0-3）—— 65 个技能让 LLM 批量打标，再人工抽检。
2. **给阵容统计补样本量/段位分桶**（P0-1）——若接口不提供，需要在页面上找统计口径说明。
3. **仙灵（wisps）强度** —— 站点只有静态表，需要外部数据源。
4. **补齐剩余装备**（20 件无数值、配方只有 55 条）—— 可手工补，量不大。
5. 克制关系（P1）等前四项落地后，用对局数据回归，而不是靠人工标注。
